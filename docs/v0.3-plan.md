# v0.3 focus: build any vehicle

Until v0.2 the server was built and tested around boats, and around the player's own example
vehicles. v0.3 drops that bias. The server builds whatever the player asks for: boats, cars,
trucks, planes, jets, helicopters, flying cars, or one assembly such as an engine that can be
saved and copied into other vehicles. It builds the way the player describes, and habits taken
from earlier fixes become optional checks.

Helm and dashboard work moved to [v0.4](v0.4-plan.md).

Work happens on the `v0.3` branch, one pull request per step.

## Step 1: cleanup (done)

- **Game facts stay enforced; habits become optional.** The writer keeps every rule that comes
  from the game or its file format (`r` on every component, left-handed axes, paint on every
  surface, attachment, part limits). The boat habits from the player's fixes become style rule
  sets, off by default and reported as warnings only: `boat_engine_room`, `bow_tip`,
  `pipe_colours` (`swhull/style.py`). They are checked with `preflight_vehicle(style=[...])`,
  or `style` in a hull spec.
- **Part bans lifted.** Any installed part can be placed except the two gearboxes the game
  deprecated. Preflight lists parts whose systems it does not model yet (modular and jet
  engines, rockets, steam, heat exchangers) as `unchecked`, never as faults. A vehicle without a
  prebuilt diesel is no longer "incomplete".
- **Reference studies removed.** `study_references` and `score_vehicle` measured how the
  player's favourite builds were made and scored new designs against them. They are gone.
  Reading and importing any vehicle stays.
- **Fewer, general tools.** `get_guide(topic)` replaces `hull_design_guide` and
  `land_vehicle_guide`, with a new start guide for any vehicle (`docs/start.md`).
  `search_parts(category=...)` replaces `search_land_parts`, with part families for every
  vehicle type. `list_game_vehicles(filter=...)` replaces `find_land_vehicles`.
  `create_vehicle(preset=...)` replaces `create_land_vehicle` and adds an `empty` preset.
  Server instructions no longer assume a boat.
- **Server renamed** from `stormworks-hulls` to `stormworks` (the package stays `swhull`). The
  setup tool moves an existing `stormworks-hulls` client entry, with its settings, to the new
  name when the player chooses to replace it.
- **Tool definitions graded by TDQS.** Every tool declares an output schema. Batch inputs
  (edit, wire and pipe operations, assembly bindings, validation observations) are plain
  objects documented in the tool description and validated before anything runs. Edit
  previews need no revision; commits do. `repair_vehicle` takes the plan ID alone, since it
  already covers the revision. `npx mcp-tdqs lint --command "uv run server.py"` reports 0
  errors, 0 warnings and 0 notes, and the tests keep it that way.
- **Fluid Spawner default.** A Fluid Spawner saved without `fluid_type` holds diesel (checked in
  game on "costal patrol v17 v2"); the definition settings now say so.

The hull and land generators stay as optional starting points.

## Step 2: physics calculator

A read-only `analyze_physics` tool for any draft or saved vehicle:

- Base-game constants are hardcoded from `sdk/data/game_constants.xml` and the
  `rom/data/realtime_values` the calculation needs. The server never writes or overrides the
  game's constants.
- Mass and centre of mass per body and overall.
- Flotation with tanks empty and full, and optional per-tank fill: whether it floats, waterline,
  trim, heel and buoyancy reserve. Buoyancy uses multiplier 10 (provisional).
- Thrust-to-weight, and wing lift against weight at a chosen airspeed, with centre of lift
  against centre of mass.
- Slope pieces count by their exact shape; tank fluid counts as 0.1 mass per litre
  (provisional).
- Returns the numbers and a side view with the waterline and centre markers.
- In-game check: the waterline of "costal patrol v17 v2", empty and full.

## Step 3: multi-body editing

- Import, edit and save vehicles with any number of bodies.
- A new part joins the body it is told to, or the body it attaches to; a part touching two
  bodies is refused.
- Edits that split a hinge, pivot or piston pair are refused; placing one creates its child
  body.
- Previews, the viewer and the calculator show all bodies at rest, with an optional body filter.
- A `view: "bodies"` mode gives each body a fixed colour with a legend, like the game's bodies
  view, and a `markers` option draws the centres of mass, buoyancy and lift.
- Loose test: import and preview "airliner" (24 bodies) and estimate its takeoff speed. The
  player does not know this vehicle well, so treat the result as rough.

## Step 4: prefabs

- Any vehicle file is a prefab, so it can be tested in game on its own. A side file in the
  server's data folder names its connection points and stores the file's hash to detect
  changes.
- Connection points are found from unconnected logic nodes and open pipe ends, and can be
  renamed.
- Tools: `list_prefabs`, `create_prefab` (a whole file, or a box cut out of a vehicle that can
  follow its pipes, shafts and wires, saved as a new vehicle file) and `paste_prefab` (refused
  on overlap unless asked to replace; reports parts that do not attach).
- Microcontrollers are copied exactly, with only their wires remapped. Multi-body prefabs are
  allowed.
- Custom tanks become an `edit_parts` operation (a seed cell or box; adds the spawner, fluid and
  fill, and checks the seal). Imports detect tanks and report their litres; the hull `tanks`
  spec uses the same code.
- Modular engines stay `unchecked` in preflight until real checks are added here.
- In-game check: copy the modular engine out of "costal patrol v17 v2" into a test hull, connect
  it, and confirm it starts and drives the propeller.

## Step 5: physics lab

A game add-on, written only when the player asks, into its own folder. It spawns test pieces and
sends readings to a local logger. Order: the buoyancy multiplier and mass scaling, tank fluid
weight (custom tanks first), water drag by coast-down, then wing lift and air drag.

## Wrap-up

- The README becomes "build any Stormworks vehicle", with new screenshots rendered by the
  server from simple camera angles.
